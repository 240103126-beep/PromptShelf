# PromptShelf · Assignment 2 Part II

| Criterion | Implementation | Evidence |
| --- | --- | --- |
| Separate development and production environments | Separate Compose projects with independent PostgreSQL databases and volumes | The test saves a prompt in dev, checks that it is absent from prod, then confirms prod stays healthy while the dev database is stopped. |
| Manual CI/CD promotion | GitHub Actions retrieves the GHCR digest from a successful verification run and uses it to deploy the same image to isolated dev and prod. | The manual demonstration uploads `promotion-evidence` with both `/api/release` responses. |
| OpenTelemetry | FastAPI sends metrics, structured logs and traces via OTLP HTTP. | The CI artifact includes `metrics.json`, `logs.json` and `traces.json`. The log and trace for a successful save share a trace ID. |
| Application metrics and dashboard | **PromptShelf Operations** displays counts, failures, duration and logs. The metrics cover prompt saves, imports, collection creation, exports and assistant requests. | `dashboard.json` contains the Grafana dashboard with environment and version filters. |
| Alerting | Grafana detects five or more HTTP 5xx responses while saving prompts in two minutes and sends an alert to the worker. | `incidents.json` records the alert that fires while the test dev database is stopped. |
| AI on-call | The worker retrieves the incident telemetry and stores a diagnosis and suggested checks generated by Gemini or local Qwen. | `model-report.json` contains the provider, telemetry and generated report. |

## Verification in GitHub Actions

[Successful observability and AI on-call run](https://github.com/240103126-beep/PromptShelf/actions/runs/43914676454). Download **stack-test-results** and open `test-results/observability/`.

To reproduce the tests and manual promotion, open **Actions → Test and deploy → Run workflow**, choose `assignment-2-part-ii` and leave the verification run ID blank. After the run succeeds, dispatch again with that run ID. The verification publishes an image to GHCR. The manual demonstration checks the published digest and both release endpoints on a fresh CI runner.

The verification uses Qwen through llama.cpp by default. A repository Actions secret named `ONCALL_GEMINI_API_KEY` selects Gemini instead.

## Local demonstration

Run from the repository root with Docker, Compose v2 and `jq` installed.

```bash
docker build -t promptshelf:local .
APP_IMAGE=promptshelf:local bash tests/observability/verify.sh
```

The test uses temporary PostgreSQL databases and synthetic data. It tears down its own containers and keeps the evidence under `test-results/observability/`.

To keep the environment running for a presentation, generate the configuration once from the repository root. Keep the files for restarts because the passwords must match the initialized volumes.

```bash
umask 077
mkdir -p .environments
for environment in dev prod; do
  printf 'POSTGRES_PASSWORD=%s\n' "$(openssl rand -hex 20)" > ".environments/$environment.env"
done
printf 'GRAFANA_ADMIN_PASSWORD=%s\nONCALL_LOCAL_MODEL_URL=http://model:8080\n' \
  "$(openssl rand -hex 20)" > observability/.env
docker compose --env-file observability/.env -f observability/compose.yaml --profile local-model up -d
bash deploy/environments.sh dev up
bash deploy/environments.sh prod up
```

- [Development app](http://localhost:8001/app)
- [Production app](http://localhost:8002/app)
- [PromptShelf Operations in Grafana](http://localhost:3000/d/promptshelf-ops/). Sign in as `admin` with your generated password.
- In Grafana, open **Explore → Tempo** and search for service `promptshelf-api`. Match the trace ID against the application log in Loki.

## Persistent hosted deployment

The hosted production workflow is [promote.yml](../.github/workflows/promote.yml). It verifies the running dev release, checks that main CI passed for the same commit, and promotes the GHCR manifest by digest. The deployment timer pulls the approved digest and the workflow waits for the production health endpoint.

1. Use a Linux Docker host with enough memory for both app/database pairs and Grafana LGTM. Configure two app origins with a reverse proxy and keep the collector, dashboard, webhook and databases internal.
2. Configure the two environment files and start observability. Set `ONCALL_IMAGE` to the tested GHCR image by digest. Configure Gemini with `ONCALL_GEMINI_API_KEY` or start the local model with the `local-model` Compose profile.
3. Install the deployment timer with `sudo env PROMPTSHELF_CONFIG_DIR=/absolute/config/path bash deploy/install-environments.sh`. The host's tokenless image pull uses a public GHCR package.
4. Set repository Actions variables `DEVELOPMENT_URL` and `PRODUCTION_URL`. With the workflow on the default branch, dispatch **Promote development image to production** with the revision from dev's healthy `/api/release`.

The public endpoints from Part I are for that submission. This Part II demonstration uses GitHub Actions runners and stops the temporary apps at the end of each run.
